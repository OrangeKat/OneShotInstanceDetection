Pair inspector

What the controls do

Model
Which matcher answers for this pair. Switching re-runs it live, so the same image shows how a sparse, dense, or classical matcher differs.
Search
Filters the pair list by instance or query filename.
Hard pairs only
Pairs that no benchmarked model solves. Start here: if every matcher misses the same pair, the problem is the pair, not the matcher.
Layers
Links draws the correspondences returned before RANSAC, reference to query — the matcher's raw answer. Residuals adds a dashed arrow from each matched point to where the homography puts it; arrow length is the model's own geometric error. Density shades where matches concentrate on each image.
Line width
Thickness of links and residual arrows. Raise it when a pair has many correspondences and the lines disappear into the image.
Response
Greys out each cell of the reference and of the query in turn and re-runs the matcher. Red cells are the ones whose removal costs matches or confidence, so the heatmap shows where the model actually looks. Slow: one matcher run per cell per image.
Keypoints
Shows the keypoints each side detected, before matching, sized by detector response. Top k keeps only the strongest k per image, which is how you check whether a region produced any usable features at all. Dense matchers have no keypoints, so the layer stays empty for them.
Point labels
Each query point is tagged with the reference keypoint index it matched, so a correspondence traces back to a source pixel.
Colours
inlier outlier residual
Ablations tab
Runs one factor at a time (keypoints, RANSAC threshold, input size, ratio) across a values list and shows each finished run beside a baseline with deltas. Jobs run serially in the background; each writes its config and git commit next to its results.
Keys
? opens this panel, Esc closes it, L R D N toggle layers, and the wheel zooms while drag pans.
