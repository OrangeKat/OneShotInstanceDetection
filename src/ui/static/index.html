Pair inspector

What the controls do

Model
Which matcher answers for this pair. Switching re-runs it live, so the same image shows how a sparse, dense, or classical matcher differs.
Search
Filters the pair list by instance or query filename.
Hard pairs only
Pairs that no benchmarked model solves. Start here: if every matcher misses the same pair, the problem is the pair, not the matcher.
Links
Draws the correspondences returned before RANSAC, reference to query. This is the matcher's raw answer, not the filtered one.
Residuals
Dashed arrow from each matched query point to where the estimated homography says its reference point should land. Long arrows are matches the geometry rejects; the arrow length is the model's own error.
Density
Occupancy of the matched points on each image. A flat map means matches are spread over texture; a hot spot means the matcher locked onto one region.
Line width
Thickness of links and residual arrows. Raise it when a pair has many correspondences and the lines disappear into the image.
Occlusion
Greys out each cell of the reference in turn and re-runs the matcher. Cells that matter are the ones where matches vanish, so this shows which part of the reference the result actually depends on. Slow: one matcher run per cell.
Point labels
Each query point is tagged with the reference keypoint index it matched, so a correspondence traces back to a source pixel.
Colours
inlier outlier residual
Mouse
Wheel zooms, drag pans, hover shows the exact coordinates.
